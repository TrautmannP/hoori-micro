## Domain errors → `Problem`

Expected domain errors are ordinary exceptions. A `@RestControllerAdvice` maps them to a
public `Problem(status, code)`:

<include meta='title="error/RecipeAdvice.java"'>../../../../examples/recipes-service/src/main/java/dev/hoori/micro/recipes/error/RecipeAdvice.java</include>

```java
public final class RecipeNotFound extends RuntimeException {}
public final class RecipeStoreFull extends RuntimeException {}
```

Unknown failures stay **500**. Public responses never contain exceptions, provider messages
or input values.

## Errors from other services

A service client throws `hoori.micro.ServiceCallException` on failure:

| Method | Content |
|---|---|
| `service()` | Name of the called service |
| `upstreamStatus()` | Provider HTTP status; `0` means no response |
| `endpoint()` | Direct HTTP contract, or `null` when no error response was received |
| `code()` | Public error code of the provider |
| `violations()` | Bounded field paths and codes; never peer messages or values |

Typical pattern: translate a known remote status into your own domain error and rethrow
everything else.

```java
@Service
public final class ShoppingService {
    private final RecipeClient recipes;

    public ShoppingService(RecipeClient recipes) {
        this.recipes = recipes;
    }

    public Recipe meal(long id) {
        try {
            return recipes.get(id);
        } catch (ServiceCallException failure) {
            if (failure.upstreamStatus() == 404) throw new RecipeMissing();
            throw failure;
        }
    }

    public static final class RecipeMissing extends RuntimeException {}
}
```

## Error priority

Admission, cancellation, deadline and mandatory cleanup take **precedence** over domain advice.
The response is released only after local child/resource drain.

| Situation | Result |
|---|---|
| Validation fails | 400 with `validation_failed`, before the business method |
| Domain error with advice | Status and code from the `Problem` |
| Untranslated `ServiceCallException` | 502; if the provider answered 503/504, that status is kept |
| Request budget expired / I/O timeout | 504 |
| Cancellation, interruption, saturation, stop | 503, no retries |
| Endpoint/version mismatch at the provider | 421, no retry |
| Unknown exception | 500 without details |

A remote validation failure is **not** presented as validation of the outer input: an
untranslated failure of an inner call becomes 502, without the provider's field paths.

## Troubleshooting

Inspect the affected process's `/metrics`; the [metrics reference](/docs/reference/metrics)
defines each local discovery, pool, admission and OpenAPI signal.

| Symptom | Check |
|---|---|
| Gateway 404 | Published route/permission declarations, `hoori_micro_catalog_fresh` and `hoori_micro_gateway_routes_withheld` |
| 502 upstream failure | Provider health and registration, catalog freshness and registry availability; a fresh catalog does not prove a provider is reachable |
| Admission-related 503 | Active/pending/rejected calls, pool saturation and stopping/cancellation failure reasons |
| Documentation-only 503 | `hoori_micro_openapi_enabled`, `hoori_micro_openapi_available` and the fixed `hoori_micro_openapi_state` reason |

An unavailable registry can leave the retained catalog usable until it expires. A missing
contract or rejected aggregate can make docs unavailable while business routes and local
readiness remain usable. Fix the indicated cause; the workers recover without a restart.
